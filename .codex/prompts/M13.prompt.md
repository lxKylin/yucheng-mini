# M13 · 首页 / 列表页适配新数据层

## 任务概述

你是一名熟练的 Taro 4 + React 18 + TypeScript + Zustand + @taroify/core 专家。请按照以下规范，**逐步完成** M13 首页 / 提醒列表适配新数据层的全部开发内容。完成每个子任务后自行验证，确认无误再进入下一个。

本模块承接 M10 / M10a / M11 / M12：项目已经从旧 `Reminder` 过渡到统一 `Medicine` 实体，并新增了 `MedicineComposer` 和药箱 Tab。M13 的目标不是重做首页或列表，而是做一次精准收口：确保首页风险中心和提醒列表只消费「提醒视角」数据，新增 / 编辑入口统一使用 `MedicineComposer`，组件字段引用全部切到 `Medicine` 新字段，并且 `reminderEnabled=false` 的药品不会混入首页或提醒列表。

## 当前项目状态

- `src/hooks/useReminders.ts` 应提供：
  - `useDerivedList()`：提醒视角，仅返回 `status !== deleted && reminderEnabled === true` 的派生药品
  - `useAllDerivedMedicines()`：药箱视角，返回所有未删除药品，本模块不应在首页 / 列表使用
  - `useReminderActions()`：包含 `markDone`、`togglePause`、`updateReminder` 等操作
- `src/hooks/useReminderSheet.ts` 应支持：
  - `openCreate(defaultReminderEnabled = true)`
  - `openEdit(id)`
  - `sheetTitle`
  - `formKey`
  - `defaultReminderEnabled`
- `src/components/MedicineComposer/` 已存在：
  - 支持 `medicineId`
  - 支持 `defaultReminderEnabled`
  - `onSuccess` 后由页面负责关闭 Sheet
- `src/pages/home/index.tsx` 和 `src/pages/list/index.tsx` 可能已经部分接入 `MedicineComposer`；请先检查现状，再做最小必要修改。
- `src/components/MedicineCard/index.tsx` 和 `src/components/ReminderDetail/index.tsx` 仍是首页 / 列表 / 详情的提醒视角组件，必须继续展示风险状态、进度、下次开药日期和已开药闭环。

## 技术约束

- 保持函数式组件 + Hooks + TypeScript 类型安全
- 优先使用 `@taroify/core` 组件；没有合适组件时再使用 `@tarojs/components`
- 不新增云数据库集合，不修改云函数扫描逻辑，不重写 M9 云开发认证和订阅消息
- 不重做药箱页，不修改 `MedicineInventoryCard`，不把药箱搜索 / 筛选逻辑复制到首页或列表
- 不使用 `useAllDerivedMedicines()` 作为首页 / 列表数据源
- 首页 / 列表仍然只展示 `reminderEnabled=true` 的药品
- 不引入库存估算，不读取或展示 `stockPerPrescription`、`estimatedStock`、`stockDays` 等字段
- 不删除 `ReminderForm` 文件，但首页 / 列表新增 / 编辑入口不应再依赖它
- 修改保持小步精准，不顺手重构我的页、药箱页、云服务或全局样式

## 子任务 4：字段名适配与组件回归

检查以下文件：

- `src/components/MedicineCard/index.tsx`
- `src/components/ReminderDetail/index.tsx`
- `src/pages/home/index.tsx`
- `src/pages/list/index.tsx`

### 4.1 字段名必须使用 `Medicine` 新字段

组件应优先使用：

- `name`
- `spec`
- `currentPrescriptionDate`
- `intervalDays`
- `remindAdvanceDays`
- `remindTime`
- `prescriptionHistory`
- `nextPrescriptionDate`
- `nextRemindDate`
- `scheduleLabel`（如需要展示服药时机）

不得继续依赖旧字段：

- `medicineName`
- `medicineSpec`
- `lastDate`
- `interval`
- `before`
- `time`
- `history`

如果某些旧字段只出现在 `ReminderForm`、迁移函数、兼容双写或注释中，可以保留；但首页 / 列表 / 风险卡片 / 详情展示逻辑不应读取它们。

### 4.2 卡片展示口径

`MedicineCard` 是提醒风险卡片，不是药箱资料卡片。应继续展示：

- 药品名称、规格
- 状态标签 `levelLabel`
- 最近开药日期 `currentPrescriptionDate`
- 周期 `intervalDays`
- 下次开药日期 `nextPrescriptionDate`
- 提醒时间 `nextRemindDate + remindTime`
- 进度条 `progress`
- `已开药` 和 `查看详情` 操作

不要在 `MedicineCard` 中展示药箱专属信息，如过期时间、资料编辑提示、提醒启用状态文案等；这些属于 `MedicineInventoryCard`。

### 4.3 详情删除语义

如果当前 `ReminderDetail` 的删除按钮用于首页 / 列表提醒视角，优先采用「关闭 / 移出提醒列表」语义：

- 确认弹窗文案说明药品资料仍保留在药箱
- 确认后调用 `updateReminder(id, { reminderEnabled: false, status: active })` 或项目中等价 API
- 成功后关闭 Sheet，Toast 提示已移出提醒列表

不要在提醒详情里直接硬删除药品，除非前置模块已经明确采用删除药品语义。

## 开发提示

- 先做静态扫描确认现状，再决定是否需要修改。M13 是收口模块，很多代码可能已经在 M11 / M12 中提前完成。
