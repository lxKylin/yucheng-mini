# 微信小程序产品方案：《开药提醒 / 长期治疗助手》

---

# 一、项目定位

## 产品定位

一个面向：

- 年轻长期治疗患者
- 患者家属

的：

# 长期治疗管理工具

核心能力：

- 开药提醒
- 续药提醒
- 复诊提醒
- 药量预测
- 长期治疗时间轴

---

## 核心目标

帮助用户：

```text
避免断药
降低治疗风险
管理长期治疗过程
```

---

# 二、目标用户

---

## 1、年轻长期治疗患者

典型场景：

- 肺癌靶向药
- 乳腺癌
- 甲状腺癌
- 慢病长期处方
- 精神类药物长期治疗

用户特点：

| 特点       | 描述     |
| ---------- | -------- |
| 年龄       | 20~45 岁 |
| 数字化能力 | 强       |
| 用药周期   | 长期     |
| 风险敏感   | 高       |
| 管理需求   | 强       |

---

## 2、家属

典型场景：

```text
子女帮助父母管理长期用药
```

需求：

- 防止断药
- 提前复诊
- 管理药量
- 接收提醒

---

# 三、第一阶段目标（MVP）

---

# MVP 核心目标

验证：

- 用户是否愿意长期使用
- 用户是否需要续药提醒
- 微信提醒是否有效
- 用户是否愿意维护药物数据

---

# MVP 功能范围

## 必须有

- 微信登录
- 添加药物
- 自动计算药量
- 自动计算提醒日期
- 微信订阅消息提醒
- 药物列表
- 风险提醒首页

---

## 不做

- OCR
- AI 分析
- 医院挂号
- 检查指标
- 家属共享
- 社区功能

---

# 四、产品核心功能设计

---

# 1、药物管理

## 药物字段设计

| 字段         | 示例       |
| ------------ | ---------- |
| 药物名称     | 洛拉替尼   |
| 规格         | 100mg      |
| 每日剂量     | 1片/天     |
| 当前库存     | 12片       |
| 开药日期     | 2026-05-13 |
| 本次开药数量 | 30片       |
| 开药周期     | 30天       |
| 提前提醒天数 | 7天        |

---

## 自动计算逻辑

### 预计用完日期

```text
预计用完日期
=
当前库存 / 每日剂量
```

---

### 提醒日期

```text
提醒日期
=
预计用完日期 - 提前提醒天数
```

---

### 2. 药量不足提醒

```text

```

### 4. 超期提醒


# 十一、为什么第一阶段推荐小程序

---

# 小程序优势

| 优势         | 原因                 |
| ------------ | -------------------- |
| 获客成本低   | 无需下载安装         |
| 微信通知强   | 用户不会关闭微信通知 |
| 适合家庭传播 | 家属转发方便         |
| 开发成本低   | 微信云开发即可       |
| MVP 验证快   | 快速上线             |

---

# 为什么不建议一开始做 App

- 用户需求尚未验证
- 安装成本高
- 推送复杂
- 运维复杂
- 审核更严格
