## 一、产品定位

### 1.1 产品名称

**愈程记** · 开药提醒

### 1.2 产品定位

一款面向**长期治疗患者及其家属**的微信小程序，聚焦"开药提醒"这一高价值核心场景。

用户可以记录药物信息、最近一次开药时间、预计用药周期和提醒时间，在接近需要重新开药时收到微信提醒，**避免断药**。

### 1.3 核心价值主张

```
不要断药
```

- **减少断药风险**：自动计算下次开药时间，提前推送提醒
- **降低记忆负担**：不再手动翻聊天记录或病历本
- **多药并行管理**：支持多种长期药物独立周期管理
- **家庭协作友好**：子女可代管父母长期用药，基于微信生态使用门槛低

## 二、目标用户

### 2.1 一线用户：年轻长期治疗患者（20–45 岁）

典型场景：

- 肺癌靶向药（如洛拉替尼）长期服用
- 乳腺癌、甲状腺癌术后维持用药
- 慢病长期处方（高血压、糖尿病、甲状腺功能异常）
- 精神类药物长期治疗

用户特点：数字化能力强、风险敏感、长期用药、主动管理意愿强。

### 2.2 二线用户：患者家属

典型场景：

- 子女帮父母管理长期用药
- 需要接收提醒、追踪开药周期
- 代为操作记录更新

### 2.3 通用慢病患者

- 高血压、糖尿病、甲状腺疾病等需定期复诊开药的用户
- 同时服用多种药物、各周期不同的用户

## 五、核心功能设计

### 5.1 药物提醒管理

#### 字段设计

| 字段                      | 类型         | 必填 | 说明                                              |
| ------------------------- | ------------ | ---- | ------------------------------------------------- |
| `medicineName`            | string       | ✅   | 药物名称，手动输入                                |
| `medicineSpec`            | string       | ❌   | 规格，如 20mg、1 盒 30 片                         |
| `currentPrescriptionDate` | YYYY-MM-DD   | ✅   | 最近一次开药日期，默认今日                        |
| `intervalDays`            | number（天） | ✅   | 开药间隔，快捷选项：7/14/28/30/45/60/90 天        |
| `remindAdvanceDays`       | number（天） | ✅   | 提前提醒天数，快捷选项：1/3/7/14/30 天，默认 7 天 |
| `remindTime`              | HH:mm        | ✅   | 提醒时刻，默认 09:00                              |
| `status`                  | enum         | —    | 系统维护：`active` / `paused` / `deleted`         |
| `note`                    | string       | ❌   | 备注，可填医院、用途、注意事项                    |
| `prescriptionHistory`     | string[]     | —    | 历史开药日期，最多保留 5 条                       |

#### 派生计算字段（不持久化，实时计算）

| 字段                   | 计算公式                                   | 说明                   |
| ---------------------- | ------------------------------------------ | ---------------------- |
| `nextPrescriptionDate` | `currentPrescriptionDate + intervalDays`   | 预计下次开药日期       |
| `nextRemindDate`       | `nextPrescriptionDate - remindAdvanceDays` | 提醒触发日期           |
| `daysLeft`             | `nextRemindDate - today`                   | 负数表示已逾期         |
| `level`                | 见下表                                     | 紧急等级，驱动 UI 颜色 |
| `progress`             | `已过天数 / intervalDays × 100`            | 周期进度百分比         |

#### 紧急等级判定

| level     | 条件                             | 颜色 |
| --------- | -------------------------------- | ---- |
| `danger`  | `daysLeft ≤ 0`（逾期或今日到期） | 红色 |
| `warning` | `0 < daysLeft ≤ 7`               | 橙色 |
| `good`    | `daysLeft > 7`                   | 绿色 |
| `paused`  | `status === "paused"`            | 灰色 |

#### 排序规则

```
danger → warning → good → paused
同级按 nextPrescriptionDate 升序
```

### 5.2 提醒通知

#### 通知方案

| 渠道         | 策略     | 说明                                                 |
| ------------ | -------- | ---------------------------------------------------- |
| 微信订阅消息 | 主渠道   | 用户每次"已开药"或新增提醒时授权，云函数定时触发推送 |
| 小程序内首页 | 兜底展示 | 进入小程序后可见所有逾期和即将到期任务               |

#### 触发规则

1. 每天 09:00 云函数 `reminder` 扫描当日需提醒数据
2. 满足条件时发送微信订阅消息（`today >= nextRemindDate`）
3. 用户点击消息进入详情页 → 执行"已开药"操作 → 自动进入下一周期
4. V1.1 新增：若用户 3 天内未处理，次日再次提醒一次

#### 提醒文案示例

```
标题：开药提醒

正文示例1：
您的「洛拉替尼」预计将在 7 天后需要重新开药，请提前安排复诊。

正文示例2：
「二甲双胍」今日需要处理开药事项，请避免断药。
```

### 5.3 首页（风险中心）

设计原则：**不做功能导航页，而是风险中心**。

#### 页面结构

1. **顶部风险提示**：「2 个药物即将断药」醒目横幅
2. **今日统计区**：逾期数 / 今日到期数 / 7 天内到期数
3. **药物风险卡片列表**：按紧急程度排序，展示剩余天数、进度条、颜色标记
4. **时间轴提示**：近期开药时间节点
5. **新增提醒悬浮按钮**

### 5.4 提醒列表页

1. 搜索框：按药物名称搜索
2. 状态筛选：全部 / 启用中 / 已暂停
3. 药物卡片列表：包含名称、最近开药日期、下次开药日期、剩余天数、状态标签
4. 支持进入详情页

### 5.5 提醒详情与编辑

1. 药物基础信息展示
2. 开药周期与提醒设置
3. 下次预计开药日期
4. 开药历史记录（最近 5 条）
5. 支持操作：编辑、暂停/启用、已开药、删除

### 5.6 已开药操作

1. 首页卡片和详情页均有「已开药」按钮
2. 点击后默认记录为当天，支持手动修改日期
3. 系统自动更新 `currentPrescriptionDate`，计算新的 `nextPrescriptionDate` 和 `nextRemindDate`
4. 当前日期插入 `prescriptionHistory` 头部，保留最近 5 条

### 5.7 我的页面

1. 用户微信信息展示
2. 订阅消息授权状态与授权入口
3. 默认提醒时间设置
4. 通知历史收件箱
5. 常见问题 / 意见反馈

## 七、关键业务流程

### 7.1 首次使用

```
进入小程序 → 微信授权登录 → 了解产品说明 → 授权订阅消息
→ 点击新增提醒 → 填写药物信息并保存 → 系统生成提醒任务
```

### 7.2 到期提醒

```
云函数定时扫描（每天 09:00）
→ 查询 today >= nextRemindDate 的 active 提醒
→ 发送微信订阅消息
→ 用户点击消息进入详情
→ 执行「已开药」→ 自动进入下一周期
```

### 7.3 已开药闭环

```
点击「已开药」→ 确认本次开药日期（默认今天）
→ 更新 currentPrescriptionDate
→ 计算新的 nextPrescriptionDate / nextRemindDate
→ 写入 prescriptionHistory
→ 页面即时展示新的下次提醒日期
```

## 十、状态设计

### 10.1 提醒任务状态（`status`）

| 值        | 含义                       |
| --------- | -------------------------- |
| `active`  | 启用中，正常等待触发       |
| `paused`  | 用户主动暂停，不再推送提醒 |
| `deleted` | 逻辑删除，不参与任何查询   |

### 10.2 紧急等级（`level`，派生）

| 值        | 含义                             | UI 颜色 |
| --------- | -------------------------------- | ------- |
| `danger`  | 逾期或今日到期（`daysLeft ≤ 0`） | 红色    |
| `warning` | 7 天内到期（`0 < daysLeft ≤ 7`） | 橙色    |
| `good`    | 7 天以上（`daysLeft > 7`）       | 绿色    |
| `paused`  | 已暂停                           | 灰色    |

## 十一、边界与异常场景

| 场景                               | 处理策略                                                   |
| ---------------------------------- | ---------------------------------------------------------- |
| 用户未授权订阅消息                 | 小程序内首页仍展示待处理提醒；我的页引导授权               |
| 用户修改开药日期                   | 实时重算 `nextPrescriptionDate` / `nextRemindDate`         |
| 用户提前开药                       | 以最新输入的 `currentPrescriptionDate` 为准重新计算        |
| 漏处理逾期提醒                     | V1.1 增加逾期后次日再次提醒一次（最多 1 次）               |
| 药物停用                           | 立即设置 `status = paused` 或 `deleted`，停止推送          |
| 多个药物同天提醒                   | 首页聚合展示，订阅消息分条发送                             |
| 间隔天数过短（< 1）或过长（> 365） | 前端表单校验，给出提示                                     |
| 云函数推送失败                     | 写入 `reminder_logs.status = failed`；不重试，依赖次日补推 |

## 十二、交互与体验原则

1. **输入尽量少**：优先选择器和快捷选项，减少手动键盘输入
2. **风险优先**：首页展示最紧急任务，而非功能入口
3. **重要操作直达**：首页卡片直接提供「已开药」按钮，无需进入详情
4. **老年友好**：字号、按钮、颜色对比度符合可读性要求
5. **即时反馈**：「已开药」后立即展示新的下次提醒日期
6. **快捷选项**：间隔 7/14/28/30/45/60/90 天；提前 1/3/7/14/30 天

## 十四、验收标准（V1.0）

1. 用户可在 1 分钟内完成首个提醒创建
2. 系统正确计算下次开药日期和提醒触发日期
3. 用户点击「已开药」后，系统自动进入下一轮周期并即时展示新日期
4. 首页可正确按紧急程度排序展示所有提醒
5. 已授权订阅消息的用户，在到期当天 09:00 可收到微信提醒
6. 提醒数据跨小程序重启后可正确恢复（云数据库持久化）
