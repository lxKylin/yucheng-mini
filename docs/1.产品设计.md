# 开药提醒小程序产品设计

## 1. 产品概述

### 1.1 产品名称

开药提醒

### 1.2 产品定位

一款帮助慢病患者、长期服药用户及家属管理“开药时间”的微信小程序。用户可以记录药物信息、最近一次开药时间、预计用药周期和提醒时间，在接近需要重新开药时收到微信提醒，避免断药。

### 1.3 产品目标

解决用户以下问题：

1. 记不清上一次什么时候开的药。
2. 不知道按当前药量大概什么时候需要再次开药。
3. 经常临近断药才发现没有提前挂号或去医院开药。
4. 需要帮家人管理长期用药，但缺少统一记录工具。

### 1.4 目标用户

1. 长期慢病患者，如高血压、糖尿病、甲状腺疾病等用户。
2. 需要长期复诊、定期开药的人群。
3. 帮父母、老人管理用药和开药节奏的家庭成员。
4. 有多种长期药物需要分别管理的用户。
5. 年轻长期治疗患者

## 2. 产品价值

### 2.1 用户价值

1. 减少断药风险。
2. 帮助用户形成稳定的开药管理习惯。
3. 降低记忆负担，避免手动翻聊天记录或病历本。
4. 让多药管理更清晰，提升家庭协作效率。

### 2.2 产品核心卖点

1. 极简录入：几步即可完成一个药物提醒。
2. 以“开药”为核心，而不是复杂的每日服药打卡。
3. 支持多药品、多提醒并行管理。
4. 基于微信生态，使用门槛低，适合中老年和家属代操作。

## 3. 使用场景

### 3.1 典型场景

1. 用户每次门诊会开 30 天药，希望在第 27 天收到提醒去复诊开药。
2. 用户同时服用 3 种长期药，每种剩余周期不同，需要分别提醒。
3. 子女帮父母记录开药时间，希望在到期前统一收到提醒。
4. 用户换药或停药后，希望快速停用某条提醒，不再收到通知。

## 4. 产品范围

### 4.1 MVP 范围

首版聚焦“开药提醒”核心闭环：

1. 新增药物提醒。
2. 记录药物名称。
3. 记录当前开药时间。
4. 记录下次开药间隔时间。
5. 设置提醒时间。
6. 到点发送微信提醒。
7. 查看全部提醒列表。
8. 编辑、暂停、删除提醒。
9. 用户在重新开药后，一键更新本次开药时间并自动推算下一次提醒。

### 4.2 后续可扩展范围

1. 家庭成员共享管理。
2. 用药记录与服药打卡。
3. 医院、科室、医生信息记录。
4. 复诊待办、挂号提醒。
5. 药盒库存估算与剩余天数计算。
6. 导出提醒记录。

## 5. 核心功能设计

### 5.1 药物提醒管理

#### 功能说明

用户可以创建一个药物的开药提醒任务。

#### 字段设计

1. 药物名称：必填，支持手动输入。
2. 药物规格：选填，如 20mg、1 盒 30 片。
3. 当前开药日期：必填，默认当天。
4. 下次开药间隔：必填，单位支持“天”。
5. 提醒提前量：必填，例如提前 1 天、3 天、7 天提醒。
6. 提醒具体时间：必填，例如 09:00。
7. 备注：选填，可填写医院、用途、注意事项。
8. 状态：启用中、已暂停、已停止。

#### 规则说明

1. 系统根据“当前开药日期 + 下次开药间隔”计算预计下次开药日期。
2. 系统根据“预计下次开药日期 - 提醒提前量 + 提醒具体时间”生成提醒触发时间。
3. 用户更新最近一次开药时间后，系统自动生成下一轮提醒。
4. 一个药物默认对应一个提醒任务，后续可扩展为多个提醒节点。

### 5.2 提醒通知

#### 功能说明

当到达提醒时间时，向用户发送微信提醒。

#### 微信小程序实现方式

由于微信小程序不能像原生 App 一样无限制主动推送，首版建议采用以下组合方案：

1. 订阅消息：用户授权后，系统在提醒到期时发送微信订阅消息。
2. 小程序内消息中心：即使订阅消息发送失败，用户进入小程序后仍可看到待处理提醒。
3. 首页红点或待提醒提示：用户打开小程序时展示已到期、即将到期任务。

#### 提醒文案建议

标题：开药提醒

内容示例：

1. 您的“阿托伐他汀”预计将在 3 天后需要重新开药，请提前安排复诊。
2. 今天需要处理“二甲双胍”的开药事项，避免断药。

#### 触发规则

1. 到达提醒时间后触发一次主提醒。
2. 若用户未处理，可增加“逾期提醒”机制，例如逾期后次日再次提醒 1 次。
3. 用户点击“已开药”后，该次提醒结束并重新进入下一周期。

### 5.3 首页总览

#### 功能说明

首页用于承载高频查看需求，让用户快速了解近期哪些药快要开了。

#### 页面内容

1. 最近待开药提醒卡片。
2. 今日需处理提醒数。
3. 未来 7 天即将到期药物。
4. 全部药物入口。
5. 新增提醒快捷按钮。

#### 展示建议

1. 按时间紧急程度排序：已逾期、今日到期、即将到期、正常。
2. 用颜色区分状态：红色表示逾期，橙色表示临近，绿色表示正常。

### 5.4 提醒列表

#### 功能说明

展示用户所有开药提醒任务，方便统一管理。

#### 列表字段

1. 药物名称。
2. 最近开药日期。
3. 预计下次开药日期。
4. 剩余天数。
5. 当前状态。

#### 支持操作

1. 搜索药物名称。
2. 按状态筛选。
3. 按最近到期时间排序。
4. 点击进入详情页。

### 5.5 提醒详情与编辑

#### 功能说明

查看单个药物提醒的完整信息，并支持修改。

#### 页面内容

1. 药物基础信息。
2. 当前开药日期。
3. 间隔时间。
4. 下次预计开药日期。
5. 提醒设置。
6. 历史开药记录。

#### 支持操作

1. 编辑提醒信息。
2. 暂停提醒。
3. 重新启用提醒。
4. 标记“本次已开药”。
5. 删除提醒。

### 5.6 已开药操作

#### 功能说明

用户在实际完成开药后，可快速记录最新开药日期。

#### 交互设计

1. 在详情页和提醒卡片上提供“已开药”按钮。
2. 点击后默认记录为当天，也支持手动修改日期。
3. 更新后自动计算新的预计开药日期和提醒时间。

#### 价值

减少重复录入，形成完整的周期管理闭环。

### 5.7 历史记录

#### 功能说明

保存每次开药完成记录，便于用户回溯。

#### 记录内容

1. 药物名称。
2. 开药日期。
3. 预计周期。
4. 实际记录时间。
5. 备注。

## 6. 页面结构设计

### 6.1 页面架构

1. 首页
2. 提醒列表页
3. 新增/编辑提醒页
4. 我的页面

### 6.2 页面说明

#### 首页

目标：快速看到最紧急提醒和关键数据。

模块：

1. 顶部欢迎区。
2. 今日提醒统计。
3. 最近到期药物卡片。
4. 未来 7 天待开药列表。
5. 新增提醒按钮。

#### 提醒列表页

目标：统一管理所有药物提醒。

模块：

1. 搜索框。
2. 状态筛选。
3. 药物卡片列表。

#### 新增/编辑提醒页

目标：最低操作成本完成配置。

模块：

1. 药物名称输入。
2. 当前开药日期选择。
3. 间隔天数选择。
4. 提前提醒天数选择。
5. 提醒时间选择。
6. 备注输入。
7. 保存按钮。

#### 我的页面

目标：管理个人设置和通知授权。

模块：

4. 常见问题。
5. 意见反馈。

## 7. 关键业务流程

### 7.1 首次使用流程

1. 用户进入小程序。
2. 查看产品说明与提醒机制说明。
3. 授权订阅消息。
4. 点击新增提醒。
5. 填写药物信息并保存。
6. 系统生成提醒任务。

### 7.2 到期提醒流程

1. 系统扫描待触发提醒任务。
2. 到达提醒时间后发送微信订阅消息。
3. 用户点击消息进入小程序详情页。
4. 用户选择“已开药”或“稍后处理”。
5. 若已开药，则生成下一周期提醒。

### 7.3 重新开药流程

1. 用户实际完成开药。
2. 在首页或详情页点击“已开药”。
3. 确认本次开药日期。
4. 系统更新最近开药日期。
5. 系统计算并生成下一次提醒。

## 9. 提醒机制与技术约束

### 9.1 关键约束

微信小程序不能保证像系统日历或原生 App 一样进行无限制后台推送，因此产品设计必须兼顾平台限制。

### 9.2 推荐实现方案

1. 使用微信订阅消息模板作为核心通知方式。
2. 使用云开发数据库保存提醒任务。
3. 使用云函数或定时任务扫描到期数据并触发通知。
4. 在小程序内保留消息中心和首页待办提示，作为提醒兜底。

### 9.3 产品侧应明确告知用户

1. 开启订阅消息后，才能收到微信提醒。
2. 若未授权订阅消息，仍可在小程序内查看到期提醒。
3. 建议用户首次设置时同步添加手机系统日历，作为双保险。该功能可作为后续版本扩展。

## 10. 状态设计

### 10.1 提醒任务状态

1. 启用中：正常等待触发。
2. 即将到期：距离提醒时间较近。
3. 已提醒待处理：已发提醒，用户尚未确认是否开药。
4. 已完成：本周期已完成开药。
5. 已暂停：用户主动关闭。
6. 已删除：逻辑删除。

## 11. 异常与边界场景

### 11.1 需要覆盖的情况

1. 用户未授权订阅消息。
2. 用户修改了开药日期，系统需重算提醒时间。
3. 用户提前开药，需以最新日期为准重新计算。
4. 用户漏处理提醒，系统是否进行二次提醒。
5. 药物停用后，提醒应立即停止。
6. 多个药物同一天提醒时，首页需聚合展示。
7. 间隔天数过短或过长时，需要前端校验合理范围。

## 12. 交互与体验建议

### 12.1 设计原则

1. 输入尽量少，优先选择器而不是复杂表单。
2. 首页优先展示“什么时候该去开药”，不要信息过载。
3. 重要操作要直达，例如首页一键“已开药”。
4. 老年用户可读性优先，字号、按钮、颜色对比要清晰。

### 12.2 关键体验优化

1. 新建时提供常用间隔快捷选项，如 7 天、14 天、30 天、60 天。
2. 提供默认提醒时间，如上午 9 点。
3. 对即将断药任务进行置顶和明显标注。
4. “已开药”操作后即时反馈新的下次提醒日期。

## 15. 验收标准建议

1. 用户可在 1 分钟内完成首个提醒创建。
2. 系统可以正确计算下一次开药日期和提醒时间。
3. 用户点击“已开药”后，系统能自动进入下一轮周期。
4. 用户能在首页快速识别最紧急的待开药任务。
5. 已授权订阅消息的用户，可在到点时收到微信提醒。

## 16. 总结

开药提醒小程序应聚焦“避免断药”这一单一高价值场景，先把“记录开药时间 - 自动计算下次时间 - 准时提醒 - 完成后进入下一周期”这条链路做完整。首版不建议一开始就做复杂的服药打卡、问诊服务或药品商城，而应优先确保提醒准确、流程简单、老年用户也能理解和使用。
