“回顾我最近 30 天的工作，或者如果时间更短，则回顾所有可用的历史记录，并找出值得打包的重复手动工作流程。

按以下顺序使用现有证据：

- 近期 Codex 会议和任务总结。
- Codex 记忆和发布摘要，以发现跨会话重复出现的模式。
- 如果启用编年史功能，则可发现 Codex 之外的重复工作。编年史功能仅用于发现重复工作；尽可能在相关源系统中确认重要细节。
- 利用现有技能、自定义代理和自动化功能，您可以重用或扩展现有功能，而不是重复开发。

广泛寻找那些重复性高、耗时长、容易出错、对上下文要求高或受益于统一流程的工作。工作流程应涵盖编码、研究、写作、规划、沟通、运营、分析和个人管理等各个环节。

仅在以下情况下对候选人采取行动：

- 至少发生过两次，或者明显有可能再次发生且再次发生成本高昂；
- 具有稳定的输入、可重复的程序和明确的输出或停止条件；
- 能显著提高速度、质量、一致性或可靠性；
- 尚未得到充分涵盖。

  选择最小合适的形式：

- 技能：可重用的工作流程或操作手册。
- 自定义子代理：适合委派的有界限的专家角色或调查任务。
- 自动化：定期或重复的检查、报告、提醒或监控。
- 跳过：过于一次性、含糊不清、敏感或证据不足的作品，不宜打包。

  首先，拟定一份精简的候选名单，内容包括：

- 重复工作流程
- 佐证材料和日期
- 频率/置信度
- 推荐形式：技能、子代理、自动化、扩展现有或跳过
- 为什么值得或不值得创建

然后只创建那些高置信度的缺失项。保持其范围窄、实用、来源明确且易于验证。不要创建推测性、重叠或过于宽泛的资产。
