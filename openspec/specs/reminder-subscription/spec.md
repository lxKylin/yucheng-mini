## Purpose

定义个人页微信提醒授权的统一订阅消息模板请求能力，确保开药日程提醒、药品过期提醒和检查/复诊提醒共享同一个用户级订阅资格状态，同时按模板 ID 解析授权结果并保留现有云函数发送链路。

## Requirements

### Requirement: 统一请求全部提醒模板

系统 SHALL 在用户通过个人页开启微信提醒时，一次性请求所有已配置的提醒订阅消息模板。

#### Scenario: 用户开启微信提醒

- **WHEN** 用户点击个人页的微信提醒授权入口
- **THEN** 系统调用微信订阅消息授权接口，并传入开药日程提醒、药品过期提醒、检查/复诊提醒三个模板 ID

#### Scenario: 模板 ID 配置为空

- **WHEN** 没有任何有效的提醒订阅消息模板 ID
- **THEN** 系统不发起微信订阅消息授权请求，并提示需要先配置订阅消息模板 ID

### Requirement: 按模板解析订阅结果

系统 SHALL 按模板 ID 分别读取微信订阅消息授权结果，并基于所有模板结果归并出本次统一授权结果。

#### Scenario: 全部模板授权成功

- **WHEN** 所有有效提醒订阅消息模板都返回 `accept`
- **THEN** 系统将本次统一授权结果视为可用，并允许个人页把用户级订阅资格更新为可用

#### Scenario: 任意模板未授权成功

- **WHEN** 任意有效模板返回 `reject`、`ban`、`filter` 或未知结果
- **THEN** 系统将本次统一授权结果视为不可用，个人页不得显示消息订阅已开启，并提示用户存在未开启或配置异常的模板

#### Scenario: 模板返回配置异常

- **WHEN** 任意模板返回 `ban` 或 `filter`
- **THEN** 系统保留该模板的异常结果用于诊断，并提示检查模板配置

### Requirement: 保持统一授权状态模型

系统 SHALL 继续使用现有用户级微信订阅资格状态表达是否存在可用订阅授权，不为三类提醒新增独立用户开关或独立状态字段。

#### Scenario: 订阅归并成功

- **WHEN** 全部有效提醒订阅消息模板都返回 `accept`
- **THEN** 系统更新现有用户级微信订阅资格状态为 `available`

#### Scenario: 订阅归并失败

- **WHEN** 任意有效提醒订阅消息模板未返回 `accept`
- **THEN** 系统不新增任何分模板订阅状态字段，也不新增三类提醒订阅开关

### Requirement: 兼容现有发送链路

系统 SHALL 保持现有云函数提醒发送链路不变，使开药日程提醒、药品过期提醒、检查/复诊提醒继续读取当前用户级订阅资格状态。

#### Scenario: 云函数检查订阅资格

- **WHEN** 任意提醒云函数准备发送订阅消息
- **THEN** 系统继续使用现有用户级微信订阅资格状态判断是否可以发送，不要求云函数读取分模板状态
