## Why

长期用药家庭通常同时管理多种药品，每周复诊或开药前需要重新盘点剩余数量。当前系统只能按固定开药间隔推算下一次开药日期，不能回答“现在大约还剩多少、还能服用几天”；当医生频繁调整剂量时，用户更难凭药盒数量判断是否需要补药。

同时，现有 `dosagePerUse` 虽然使用 `number` 存储，但表单在输入过程中立即将字符串转成数字，导致 `0.5`、`0.25` 等常见半片、四分之一片剂量难以正常录入。需要先补齐小数剂量交互，再在其基础上提供可信、可校准的余量估算。

## What Changes

- 优化每次用量输入：片剂提供 `1/4 片`、`1/2 片`、`1 片`、`1.5 片`、`2 片`快捷值，并保留最多两位小数的自定义输入。
- 新增可选的药品余量跟踪；用户录入某次盘点后的实际总量和盘点日期，系统按当前每次用量与每日次数动态派生预计剩余数量和预计可用天数。
- 明确余量是“按当前计划估算”，不将其表述为实际服药结果；用户可以随时重新盘点并校准基准数量。
- 规则用药支持自动估算；按医嘱、每日次数为 0 或用户主动暂停估算时，仅保留手动库存，不自动扣减。
- 调整剂量时先按旧剂量结算到生效日，再以结算后的预计余量作为新基准，避免新剂量反向重算历史消耗。
- 将“本次已开药”流程与库存校准衔接：已启用余量跟踪时允许填写开药后的当前药品总量，也允许明确选择稍后盘点。
- 在药箱卡片展示预计剩余数量、预计可用天数和估算状态，并提供“余量不足”筛选；默认列表顺序保持稳定，不因每日派生变化自动重排。
- 更新产品设计与开发计划中“近期不做库存管理、药箱不展示余量”的旧边界，使文档与新能力一致。
- 不新增逐次服药提醒或打卡、药品批次管理、家属共享、库存不足订阅消息，也不使用每日健康状态自动扣减具体药品。

## Capabilities

### New Capabilities

- `medicine-inventory-estimation`: 定义小数剂量录入、可选余量跟踪、按计划估算、开药后校准、剂量变更结算和药箱余量展示。

### Modified Capabilities

- 无

## Impact

- 影响统一 `Medicine` 类型、存量数据迁移、余量派生工具、Zustand 药品 store 和云端 `medicines` 更新链路。
- 影响 `MedicineComposer`、药箱卡片与筛选、提醒详情以及首页/提醒列表中的“已开药”交互。
- 存量药品默认关闭余量跟踪，不产生无依据的库存数字；现有开药提醒、过期提醒和检查提醒行为保持不变。
- 不新增第三方依赖；继续使用 React 18、Taro 4.2、TypeScript、Zustand、taroify 和现有云数据库能力。
