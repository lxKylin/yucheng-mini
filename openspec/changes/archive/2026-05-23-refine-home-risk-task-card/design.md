## Context

首页当前通过 `useHomeRiskFeed` 输出统一待办池，并由 `HomeRiskCard` 在首页内渲染开药和检查两类事项。这个状态已经避免了早期「开药列表 + 检查摘要」的分区问题，也没有再直接嵌入完整 `MedicineCard` 或 `CheckupCard`。

但现在的首页卡片仍然像管理列表摘要：顶部先展示类型和标题，中间用两个大信息块展示目标日期和提醒时间，底部两个等宽大按钮占据很强视觉重量。对于首页来说，用户最先需要的是判断「哪件事最急、为什么现在处理、处理后会发生什么」，而不是像进入检查 Tab 后那样浏览完整字段。

本设计只调整首页风险待办卡片的信息架构和展示字段，不改变底层排序、统计、完成动作或详情弹层。

## Goals / Non-Goals

**Goals:**

- 首页待办卡片第一眼表达风险状态，例如「逾期 2 天」「今天到期」「10 天后」。
- 业务类型「开药 / 检查」保留为来源标签，但不抢占风险主层级。
- 用一句首页行动摘要解释为什么现在要处理，避免只把业务字段拼成列表。
- 将目标日期和提醒时间压缩为轻量时间摘要，降低卡片高度。
- 操作区更像首页快捷处理入口：主操作明确，详情入口次级。
- 开药和检查保持同一套卡片结构，只替换业务摘要和动作文案。

**Non-Goals:**

- 不改变 `useHomeRiskFeed` 的排序、截取数量或风险统计口径。
- 不改变开药提醒或检查提醒的数据模型、状态机、完成逻辑。
- 不改变提醒 Tab、检查 Tab、药箱 Tab 的业务卡片。
- 不新增首页检查创建入口或多类型新增弹窗。
- 不重做首页 Hero、底部导航或整体视觉系统。

## Decisions

### 决策 1：风险状态作为卡片首层信息

首页卡片顶部应从「类型 + 标题 + 状态」调整为「风险状态 + 业务类型」。风险状态可以使用 `levelLabel` 或基于 `daysLeft` 生成更明确的首页文案：

```text
逾期 2 天                         检查
血脂
复诊前建议完成，关联瑞舒伐他汀
目标 05-21 · 提醒 05-14 09:00
                         详情   完成检查
```

备选方案是继续把标题放在第一视觉层级。该方案不采用，因为首页是风险中心，首层信息应回答「急不急」，标题回答「是什么」。

### 决策 2：用首页行动摘要替代字段堆叠

`primaryMeta` / `secondaryMeta` 现在更像业务字段摘要，例如规格、周期、医院、关联药品。首页卡片需要一条更有判断感的行动摘要：

- 开药：`当前周期已结束，处理后进入下一轮`、`避免断药，建议今天记录已开药`。
- 检查：`复诊前建议完成，关联瑞舒伐他汀`、`已到目标检查日，完成后可在详情设置下一次`。

实现上可以在 `useHomeRiskFeed` 中补充 `actionSummary`、`timeSummary`、`primaryActionLabel` 等首页展示字段，也可以在 `HomeRiskCard` 内部根据现有字段派生。若同一文案会被多个组件复用，优先放在 `useHomeRiskFeed` 邻近工具中，避免 JSX 里堆条件表达式。

### 决策 3：日期信息改为一行轻量摘要

当前两个日期块适合详情页或管理列表，但首页会显得重。首页应使用一行摘要，例如：

```text
目标 05-21 · 提醒 05-14 09:00
```

如果年份对理解很重要，可以保留完整日期；如果移动端空间紧张，可以采用 `MM-DD`，但必须保证目标日期和提醒时间仍可理解。详细信息仍由详情弹层承载。

### 决策 4：操作区改成主次分明的轻量布局

首页操作区不应继续使用两个 50% 等宽大按钮。推荐布局是主操作保持可点击面积和风险色，详情入口使用文字按钮、浅色按钮或较小次按钮：

```text
                         查看详情   完成检查
```

主操作文案应比现在更明确：

- 开药：`记录已开药` 或保留 `已开药`，实现时优先考虑移动端宽度。
- 检查：`完成检查`，避免只有 `完成` 时语义过短。

事件边界保持不变：点击主操作不得同时触发卡片详情。

### 决策 5：继续复用现有视觉系统

样式应继续沿用当前医疗绿色、浅色卡片和风险色。业务类型标签使用低饱和度胶囊或右上角小标签；风险状态使用卡片首层文字、左侧风险线、状态色或标签组合表达，但不要引入新的色彩体系。

## Risks / Trade-offs

- 首页摘要过度智能化导致文案不准确 -> 先使用基于 `daysLeft`、`type`、关联药品/医院等确定字段的保守文案，不推断用户病情。
- 日期压缩后信息不足 -> 保留详情入口，并确保摘要仍包含目标日期和提醒时间。
- 主操作变轻后可点击性下降 -> 主操作仍保持足够触控面积，只降低视觉占比，不降低可用性。
- 文案过长导致移动端换行难看 -> 行动摘要限制为一到两行，标题和摘要都要允许自然换行并避免遮挡按钮。
- 派生字段过多污染核心模型 -> 展示字段只存在于 `HomeRiskFeedItem` 或首页邻近工具，不写回 `Medicine` / `CheckupReminder` 类型。
