## Context

个人页当前由用户资料卡片和设置列表组成，设置列表已包含「订阅消息授权」「默认提醒时间」「默认提前天数」。这类入口都属于低频配置项，新增「联系作者」适合继续放在同一设置列表中，避免打断首页、提醒列表和检查列表的核心任务流。

本次需求只需要展示作者微信号并提供复制能力，不需要接入微信客服、二维码识别、云端配置或新的用户数据模型。由于微信号属于发布配置，推荐集中放在常量文件中，页面只消费该常量。

## Goals / Non-Goals

**Goals:**

- 在个人页提供明确、低干扰的「联系作者」入口。
- 点击入口后使用原生确认弹窗展示作者微信号和简短说明。
- 弹窗提供「取消」和「复制」两个动作，用户确认后复制微信号到剪贴板。
- 复制成功和失败都给出可理解的 Toast 反馈。
- 保持个人页现有卡片、菜单项、提醒授权和默认设置行为不变。

**Non-Goals:**

- 不展示微信二维码。
- 不接入微信客服会话或企业微信客服。
- 不新增反馈表单、消息收件箱、数据库字段或云函数。
- 不改变用户昵称、头像、订阅授权和默认提醒设置逻辑。

## Decisions

### 使用原生确认弹窗承载微信号

采用 `Taro.showModal` 展示「联系作者」弹窗，标题为「联系作者」，内容包含 `微信号：<作者微信号>` 和一句反馈说明，按钮为「取消」与「复制」。

原因：这个需求是一次性轻量确认，不需要复杂表单或持续展示。原生弹窗更符合微信小程序用户预期，也天然提供取消和确认按钮。

微信小程序原生弹窗限制 `confirmText` 最多 4 个中文字符，因此确认按钮使用「复制」而不是「复制微信号」。

替代方案：使用现有 `BottomSheet` 展示联系信息。该方案视觉更可控，但对一个只需复制微信号的低频动作偏重，本次不采用。

### 微信号集中配置

在常量层新增作者微信号常量，例如 `AUTHOR_WECHAT_ID`，个人页从常量读取后展示和复制。

原因：微信号是发布配置，不应散落在 JSX 文案中。集中配置便于上线前替换，也能让后续扩展联系方式时有明确入口。

替代方案：直接在 `src/pages/profile/index.tsx` 中硬编码微信号。该方案改动更少，但后续维护和检查不够清晰，本次不采用。

### 联系入口复用个人页设置项结构

新增入口放在「默认提前天数」之后，使用现有 `profile-page__menu-item`、`profile-page__menu-copy`、`profile-page__menu-label`、`profile-page__menu-desc` 和 `profile-page__menu-value` 风格。

原因：截图中的个人页已经形成白色设置卡片列表，新增入口作为最后一项最自然，也不会影响授权开关和默认设置的操作区。

替代方案：放在用户资料卡片里或独立大卡片中。资料卡片更像身份信息，独立大卡片会提升低频入口视觉权重，本次不采用。

### 复制动作只在用户确认后执行

点击菜单项只打开弹窗，不直接复制；只有用户点击「复制」后才调用 `Taro.setClipboardData`。

原因：用户点击入口可能只是想查看联系方式，直接写剪贴板会有突兀感。确认后复制能让操作意图更明确。

## Risks / Trade-offs

- 作者微信号打包在小程序前端中，属于公开信息 → 仅放置适合公开添加的微信号，不放置私人敏感联系方式。
- 未配置真实微信号会导致复制无效信息 → 实施前需要确认并替换 `AUTHOR_WECHAT_ID` 的真实值。
- 原生弹窗内容排版能力有限 → 文案保持短句，避免在弹窗中塞入长说明。
- 复制 API 在少数环境可能失败 → 捕获失败并提示用户手动复制或稍后重试。
