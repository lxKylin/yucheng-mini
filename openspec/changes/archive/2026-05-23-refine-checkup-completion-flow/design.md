## Context

检查提醒目前已有独立数据域、检查 Tab、详情弹层、首页风险集成和完成历史。现有完成路径分裂为两类：详情页中内嵌「完成本次检查」表单，可以填写备注和下一次检查日期；首页和检查列表中的「完成检查」按钮只弹出确认框，确认后直接调用完成动作并将提醒置为已完成。

这种分裂会让用户在最常用的快捷入口里失去关键选择：逾期检查无法确认实际完成日期，也无法当场安排下一次检查。完成后再编辑提醒只能改变字段，不能自然表达「这次已完成并进入下一轮」。

## Goals / Non-Goals

**Goals:**

- 让首页、检查 Tab、详情页的「完成检查」进入同一个完成流程。
- 在完成时确认实际完成日期，默认今天，并限制不能晚于今天。
- 让用户在完成时一次性决定是否设置下一次检查。
- 保留完成历史，支持备注记录，并保证状态随下一次日期正确流转。
- 让详情页回到查看和管理提醒的角色，完成表单由任务型面板承载。

**Non-Goals:**

- 不重做检查提醒创建/编辑表单。
- 不修改检查提醒云函数、订阅模板或发送时间窗口。
- 不改变首页风险排序、检查列表筛选规则或统计口径。
- 不改变开药提醒的完成流程，但可以复用其底部 Sheet 交互经验。
- 不引入自动推算下一次检查日期的复杂规则；下一次检查日期仍由用户明确选择。

## Decisions

### 决策 1：新增统一的完成检查 Sheet

所有「完成检查」入口打开同一个底部 Sheet，例如 `CheckupCompletionSheet`。面板包含实际完成日期、结果备注、下一次检查日期，以及「完成不设下次」「完成并设下次」两个动作。

备选方案是继续在首页/列表使用确认弹窗，在详情页保留完整表单。该方案不采用，因为入口行为继续不一致，且逾期场景仍无法在快捷路径里确认真实完成日期。

### 决策 2：实际完成日期是完成动作的必填语义

完成检查时始终传入 `doneDate`。面板打开时默认今天，用户可以改为今天之前的日期；日期不得晚于今天。逾期检查不应直接按点击确认时间静默完成，而应让用户确认这次检查实际发生在哪一天。

日期选择范围可以保守设置为不晚于今天，起始日期可使用当前检查检查日期附近或较早日期；若实现中无法可靠确定最早日期，至少必须保证不能选择未来日期。

### 决策 3：状态由是否设置下一次检查决定

完成动作仍使用一条业务规则：有下一次检查日期时，记录历史后将提醒保持或恢复为 `active`，并更新 `targetDate`；没有下一次检查日期时，记录历史后将提醒置为 `done`。

这条规则应成为所有入口的唯一完成语义，避免出现「用户已经设置了新检查日期，但状态仍是 done」的情况。

### 决策 4：详情页只保留完成入口，不长期嵌入完整完成表单

详情页继续展示检查信息、暂停/恢复、编辑、删除和完成历史。对于未完成的有效提醒，详情页提供「完成检查」按钮，点击后打开统一完成 Sheet。这样详情页不承担复杂任务表单的常驻展示，用户从首页、列表、详情进入时也能看到同一套字段和按钮。

### 决策 5：复用开药逾期完成体验，但保持检查领域独立

开药的 `DoneDateSheet` 已经建立了「逾期时确认实际日期」的交互心智。检查完成面板可以复用视觉结构、文案密度和校验方式，但不应把检查逻辑塞进药品组件或药品 store。检查仍使用 `checkupStore.completeCheckup` 和 `CheckupReminder` 数据域。

### 决策 6：已完成提醒通过轻量面板重新安排

`done` 表示本轮完成且当前未安排下一次提醒，不应被视为不可恢复的归档状态。已完成详情页提供「重新安排检查」主动作，打开轻量面板设置下一次检查日期、提前提醒天数和提醒时间。保存时将提醒恢复为 `active`，清空订阅发送去重字段，并保留已有完成历史。

备选方案是让用户点击「编辑提醒」后自行修改日期。该方案不采用，因为编辑字段不等于恢复追踪，容易产生「日期变了但状态仍是已完成」的困惑。

## Risks / Trade-offs

- 入口从轻确认变为 Sheet，操作步数略增加 -> 面板默认今天，主按钮清晰，正常今日检查仍可快速完成。
- 用户误选下一次检查日期为今天或过去日期 -> 保存前校验下一次检查日期必须晚于或至少不同于实际完成日期，避免立即再次进入逾期/今日状态。
- 详情页移除常驻表单后，用户可能少一个可见填写区 -> 在详情页保留明确「完成检查」主按钮，并在 Sheet 中承载同样字段。
- 旧数据中已有 `done` 状态提醒 -> 本变更不迁移历史数据；仅保证后续通过统一流程产生的记录状态正确。
- 已完成重新安排和编辑入口语义接近 -> 已完成状态不展示编辑入口，只保留「重新安排检查」和删除；编辑仍用于修改正在追踪的提醒信息。
- 与正在进行的首页卡片视觉变更相邻 -> 本变更只接管主操作行为，不改变首页卡片信息层级和样式目标。
