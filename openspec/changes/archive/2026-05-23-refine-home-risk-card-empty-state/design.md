## Context

`unify-home-risk-feed` 已经将首页从「最近开药提醒 + 紧急检查」改为统一「优先待办」。当前首页通过 `useHomeRiskFeed` 合并开药提醒和检查提醒，并在列表里按类型渲染 `MedicineCard` 或 `CheckupCard`。

这个实现满足了风险排序，但视觉语言仍然来自两个完整管理页：开药卡片强调周期、进度和两个横向操作按钮，检查卡片强调检查日期、关联药品和完成按钮。它们放在同一个首页列表时，信息密度和按钮结构不一致，用户容易感到两种卡片不是一个系统。空状态也存在语义问题：文案说可以新增开药或检查提醒，但首页右下角 `+` 实际只打开开药提醒创建流程。

本设计延续首页作为风险中心的定位，只收紧首页展示层和空状态文案，不改变底层业务域。

## Goals / Non-Goals

**Goals:**

- 首页优先待办使用统一的轻量卡片布局展示开药和检查事项。
- 用户可以一眼看出事项来源、风险状态、检查日期、提醒时间和下一步操作。
- 首页 `+` 的语义保持单一：新增开药提醒。
- 空状态同时给出检查提醒新增路径，但不把检查创建能力搬到首页。
- 保留当前 `useHomeRiskFeed` 的统一排序和统计行为。

**Non-Goals:**

- 不合并 `MedicineCard` 与 `CheckupCard` 的完整业务卡片。
- 不改变提醒 Tab 或检查 Tab 的列表卡片设计。
- 不改变开药提醒和检查提醒的数据模型、状态机、完成逻辑或云端同步。
- 不新增首页多类型新增弹窗。
- 不调整底部 Tab 结构。

## Decisions

### 决策 1：首页新增轻量待办展示层

首页应使用专用的首页待办卡片展示 `HomeRiskFeedItem`。这个卡片可以是独立组件，也可以先在首页文件内提取为局部组件，但它的职责只限于首页风险列表展示。

统一卡片建议结构：

```text
┌────────────────────────────────────┐
│ [开药/检查] 标题              风险标签 │
│ 检查日期 YYYY-MM-DD  提醒 YYYY-MM-DD HH:mm │
│ 规格/周期 或 检查类型/医院/关联药品        │
│                              主操作/详情 │
└────────────────────────────────────┘
```

备选方案是继续包裹 `MedicineCard` 和 `CheckupCard`，只调整外层样式。该方案不采用，因为两个业务卡片内部信息结构差异较大，外层样式无法消除信息重复和按钮不一致的问题。

### 决策 2：风险视觉优先于业务类型视觉

首页待办卡片的风险状态应使用统一规则表达：逾期/危险、今日或临近、正常。业务类型标签使用低饱和度标签，只表达「开药」或「检查」来源，不承担风险颜色。

这样可以避免截图中的问题：检查标签和开药标签分别使用不同色系后，用户注意力先被业务类型吸走，而不是先看到「哪件事最急」。

### 决策 3：动作文案保持业务差异，但布局保持一致

统一卡片可以保留不同主操作：

- 开药提醒：主操作为「已开药」，次操作为「查看详情」。
- 检查提醒：主操作为「已完成」，次操作为「查看详情」或进入检查详情。

动作区布局应保持一致，避免一个卡片是双按钮大操作区、另一个卡片是右下角小按钮。实现时可以先采用「主操作按钮 + 详情文字/按钮」的统一结构。

### 决策 4：空状态明确首页 `+` 的能力边界

当没有任何开药或检查记录时，首页空状态应明确：

- 右下角 `+` 用于新增开药提醒。
- 检查/复诊提醒需要前往「检查」Tab 新增。

建议文案方向：

```text
还没有提醒
先建立第一条开药提醒，首页会优先显示逾期、今天和临近事项。
点击右下角 + 新增开药提醒
检查/复诊提醒可在「检查」页新增
```

当已有记录但当前没有待处理事项时，空状态不应再引导新增，而应表达当前节奏稳定，并保留顶部「提醒 / 检查」入口。

### 决策 5：派生字段只补充首页展示需要

如果统一卡片需要更稳定的展示字段，可以在 `useHomeRiskFeed` 或邻近工具中补充首页展示文案，例如 `primaryMeta`、`secondaryMeta`、`remindText`、`primaryActionLabel`。这些字段只服务首页，不应反向修改 `DerivedReminder` 或 `DerivedCheckupReminder` 的核心模型。

## Risks / Trade-offs

- 首页卡片过度抽象 → 只抽象首页需要的显示字段和动作，不把完整业务卡片合并成通用大组件。
- 首页信息过少导致用户需要频繁点详情 → 保留检查日期、提醒时间和一行关键辅助信息，详情仍交给业务页或详情弹层。
- 空状态提示检查入口但没有明显按钮 → 可以使用文字入口或沿用「检查」Tab 顶部入口；不新增首页检查创建按钮，保持首页主新增语义清晰。
- 新组件引入样式漂移 → 复用现有医疗绿色、浅卡片、风险色、`StatusTag` 或等价视觉规则，避免新增一套色彩系统。
- 事件处理差异导致误触 → 卡片点击、主操作、详情操作需要明确事件边界，检查完成按钮不得同时触发进入检查页。
