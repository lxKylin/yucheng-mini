## Why

当前个人页的微信提醒授权只请求一个模板 ID，但产品中已经存在开药日程提醒、药品过期提醒、检查/复诊提醒三类订阅消息。用户以为一次开启了微信提醒，实际只有单个模板进入授权流程，另外两类提醒可能没有可用订阅资格。

本次变更先采用轻量修法：保持一个统一的“微信提醒授权”入口和一个用户级订阅资格状态，但前端一次性请求三类订阅消息模板，先把现有提醒能力的授权链路打通。

## What Changes

- 个人页点击开启微信提醒时，请求常量中配置的全部订阅消息模板 ID。
- 订阅结果按模板 ID 分别解析，只有全部模板都返回 `accept`，本次授权才视为可用。
- 当任意模板未返回 `accept` 时，个人页不显示消息订阅已开启，并提示用户对应的未开启或配置异常原因。
- 当模板返回 `reject`、`ban` 或 `filter` 时，保留模板级结果用于提示和诊断。
- 不新增三套用户开关，不拆分三套用户级订阅状态，不改变现有云函数发送模型。

## Capabilities

### New Capabilities

- `reminder-subscription`: 覆盖小程序端统一微信提醒授权入口，以及三类订阅消息模板的一次性请求和结果归并规则。

### Modified Capabilities

- 无

## Impact

- 影响 `src/constants/index.ts` 中订阅模板 ID 的类型和命名表达。
- 影响 `src/services/wechatReminder.ts` 的模板 ID 读取、授权请求和结果归并逻辑。
- 影响 `src/pages/profile/index.tsx` 的授权结果消费和用户提示文案。
- 不涉及云函数发送逻辑、数据库结构、用户级订阅状态字段拆分，也不引入新的依赖。
